# Design notes

Non-obvious facts about the API that the code no longer carries as comments ([AC-08.12](../specs/008-simplification/spec.md)). One bullet each; the decisions behind them are in the [ADRs](adr/README.md), the contract in [API contracts](api-contracts.md).

## Process and HTTP

- **Instrumentation loads first.** `node --import ./dist/instrumentation.js dist/main.js` patches `http`, `express` and `pg` before they are required, so `instrumentation.ts` may not import application code. It starts the SDK only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set and never stops the API from booting.
- **`bodyParser: false` in `main.ts`.** Better Auth reads the raw request stream on `/api/auth/*`; `IdentityModule` re-adds the JSON parser (100 kB, urlencoded off) for every other route.
- **Auth middleware runs in front of the Better Auth handler** (the module's `middleware` option), because Nest middleware would run after it: route allowlist (anything else under `/api/auth` is 404), then the 16 kB body cap, then the client address.
- **The 16 kB cap wraps `request.push`**, not a `data` listener: a listener would start the stream before the handler attaches and lose chunks. A declared `Content-Length` over the cap answers 413 before anything is read; chunked bodies are counted as they arrive.
- **The client address is one trusted header.** `clientIpMiddleware` drops any client-sent `x-tt-client-ip` and writes the resolved address there; Better Auth's limiter reads only that header. `req.ip` follows `X-Forwarded-For` only through the `TRUSTED_PROXIES` CIDRs (Express `trust proxy`); with none it is the TCP peer.
- **Throttlers are two global guards.** The per-address one runs before the auth guard so floods are bounded before any session lookup, and refuses (429) a request with no resolvable address instead of giving it a bucket; the per-user one runs after authentication. Each applies only its named throttler and answers a plain `Retry-After`. Health probes skip both.
- **Bearer only.** The auth guard hands only the `Authorization` header to Better Auth, so a session cookie alone never authenticates `/api/v1`.
- **No ETag.** Express's automatic weak ETag is turned off; updates are last write wins (ADR-0020).
- **Exit code 0 on SIGTERM.** After all shutdown hooks Nest re-raises the signal, which ends the process with 143; `GracefulExit`, a root-module provider whose hook runs last, turns that final re-raise into `exit(0)`. It relies on a Nest internal; the compose smoke (`docker compose stop api` exits 0) catches a change.
- **Exception text is never echoed.** A domain error's message is a fixed literal passed to `super()` (ids and counts go to `details`, never into the message), framework 4xx use a fixed message per status: exception messages can carry paths, query strings, bodies or row values. Unexpected errors log `{ name, code }` only.
- **Domain errors carry their meaning, not HTTP.** Each declares `code`, `kind` (`validation` · `not_found` · `conflict` · `rule`), a public message and optional `details`; the filter's `DOMAIN_ERROR_STATUS` is the only kind → status table. Adding an error is one class: nothing to register. Field errors extend `InvalidField`, whose message is `Request validation failed.` and whose `details` are `[{ field, message }]`, the same envelope the `ValidationPipe` produces.
- **OpenAPI error prose stays hand-written.** The per-route descriptions ("TASK_NOT_FOUND: unknown, deleted, or owned by another user…", "wins over 422") are not generated from the error classes, because the published contract must stay byte-identical; `tasks.openapi.spec`/`teams.openapi.spec` instead check that every declared code is documented and only under the status of its kind.

## Module structure

- **Tasks owns the interface it needs from Teams.** `TeamDirectory` lives in `tasks/application/interfaces/`, so the tasks use cases compile against their own module only; `tasks.module.ts` binds it with `useExisting: TeamLookup` (same instance as the one `TeamsModule` exports, no second provider). A typed `bindExisting()` helper makes the compiler check that `TeamLookup` structurally satisfies `TeamDirectory`, since `TeamLookup` cannot `implements` an interface from another module without importing it.
- **`isOverdue` is computed in application**, not in the response DTO: it is a domain rule (`Task.isOverdue`) evaluated against the clock, and presentation may not import the module's domain. `toTaskView()` also filters the teams to the task's own and sorts them by name, case-insensitively, ties by id.
- **DTOs get `TaskStatus` through `application/interfaces`**, which re-exports the domain value object: the enum is needed for `@IsEnum` and the OpenAPI schema, and the re-export keeps `presentation-not-to-domain` free of exceptions.
- **Only module files cross modules.** `contexts-isolated` forbids any other file from importing another module; `context-wiring` lets a module file import only the other module's file and its exported providers (`application/*.service.ts`). The shared kernel (`shared/domain`: `DomainError`, `Owner`, `Clock`) is not a module and stays importable from every layer.

## Logging and telemetry

- **`route` is recorded by an accessor.** Express assigns `req.route` for every route layer and Nest's catch-all middleware route overwrites the handler's, so `route-template.ts` defines a setter on `req.route` before routing (in `genReqId`) and keeps the last non-wildcard template. It depends on Express 5 internals; the `/api/v1/tasks/:id` logger test guards it.
- **The request serializer runs at request start**, before routing, so `req.url` is the path without query string; the route template is added to the completion line when the response is written.
- **`traceId` is the request id when there is no trace.** The same fallback the error envelope uses; with a span the mixin supplies the real `traceId` and `spanId`. A client `X-Request-Id` is echoed only if it matches `^[A-Za-z0-9._-]{1,128}$`, which keeps log injection out of the id.
- **The pino instrumentation is off** (`sdk-options.ts`): it would add `trace_id`/`span_id` next to the logger's fields and ship pino records over OTLP. `autoDetectResources` is off too, so the resource has only the service name. A disabled auto-instrumentation is simply absent from the list.
- **Exported spans are not scrubbed** (query strings, exception text, client address, SQL text): see [observability](../operations/observability.md#traces-when-enabled).
- **`pino-pretty` is a dev dependency.** `LOG_PRETTY=true` without it (the production image) falls back to JSON with one warning.
- **Redaction paths repeat each pattern to depth 3**, because pino wildcards match one level; names with a dash use the bracket form.
- **Better Auth log messages are sanitized** (URL query strings stripped, emails masked) and only `code`, `status`, `statusCode` and `name` of object arguments are forwarded.

## Database

- **The pg driver adapter opens no connection on `$connect`**, so the API probes with `SELECT 1` at boot and fails fast; on failure the pool is closed with a short grace, because closing waits for pending connection attempts that only end at the OS TCP timeout against a black-holed host.
- **pg is bounded at the source:** connect timeout 2 s, `query_timeout` 5 s. `query_timeout` is client side (the driver stops waiting, PostgreSQL keeps running the statement); there is no `statement_timeout`. Readiness keeps one `SELECT 1` outstanding and waits on it for 1.5 s, so probes never pile up on a hung pool and `/ready` recovers within seconds of the database returning.
- **List reads run in one `RepeatableRead` transaction** with their `count(*)`, so the page and the total come from one snapshot.
- **Name uniqueness is decided by PostgreSQL.** `lower(name)` partial unique indexes are the authority; the repository's duplicate check is a fast path and a concurrent create is settled by the index (letter-case-only renames exclude the team itself).
- **`TeamName.equals` approximates `lower()`.** On postgres:17-alpine (musl) `lower()` leaves circled letters (U+24B6–U+24CF) and Unicode 14+ code points (e.g. U+A7D0) unchanged, so `equals()` can see a collision the unique index does not; the index decides (only the in-memory fake is affected). `team-name-collation.int-spec` pins both lists: if DIVERGE fails after an image upgrade, move those rows to AGREE, never weaken the test.
- **A foreign-key violation on task team links becomes `UnknownTeams` without ids**; the use case asks `TeamDirectory` which ids are missing, so foreign and never-existing teams are indistinguishable.
- **Task links are diff-synced** so unchanged links keep their row and `created_at`. Deleting a team is one transaction: soft delete, one set-based `UPDATE` bumping `version`/`updated_at` of the owner's linked live tasks, then `DELETE FROM task_teams`.
- **A single status filter is an equality** (`status = $n`), not `= ANY(...)`: only the equality lets `tasks_owner_status_created_idx` return rows already ordered. `team_ids` are ordered by the uuid so `task_teams_pkey` returns them sorted without a Sort node. `ORDER BY` comes only from a whitelist and always ends with `id`.
- **A `date` column travels as midnight UTC**; reading and writing in UTC keeps the calendar day independent of the server time zone. `DueDate` uses `setUTCFullYear` because `Date.UTC` maps years 0 to 99 to 1900 to 1999.
- **Malformed ids skip the query** (the uuid cast would fail) and read as "not found".

## Tests

- **Jest 30 ignores a per-project `testTimeout`.** The 120 s timeout of the integration and e2e projects is set by `jest.setTimeout()` in `test/support/after-env.ts`; `effective-timeout.ts` reads jest-circus's internal `TEST_TIMEOUT_SYMBOL` to prove it (verified on 30.5). Unit tests keep the 5 s default.
- **One PostgreSQL container per Jest run.** `global-setup.ts` starts it and migrates a template database; every test file clones it (`CREATE DATABASE … TEMPLATE`) and drops the clone after its apps and clients are closed (`DROP … WITH (FORCE)` ends leftover connections).
- **Time-zone tests run in a child Jest process** (`in-time-zone.ts`, probes in `test/probes/`): setting `process.env.TZ` inside a test has no effect because Jest sandboxes `process.env`. The probe timeout stays below the parent's.
- **A TCP proxy stands in for "the database going away"** (`test/support/tcp-proxy.ts`): `stop()` refuses connections, `blackhole()` accepts and stays silent, so tests never touch the shared container.
- **Architecture rules are tested with `node:test`**, not Jest: dependency-cruiser is ESM-only. The fixture cruise runs with the fixture as working directory because dependency-cruiser resolves tsconfig paths (`@test/*`) against it.
- **nestjs-pino keeps its root logger in module state**, so a log-capturing spec boots one app per file; pino-http writes the completion line on the response's `finish`, so tests wait for the line instead of reading it right away.
- **The telemetry e2e compiles its fixture once** (`test/telemetry/tsconfig.json` into `node_modules/.cache`) because the generated Prisma client cannot run through ts-node.

## Contract and generated client

- **The contract is exported offline.** `pnpm openapi:export` builds the API and runs `dist/openapi/export.js`, which creates `AppModule` in Nest `preview` mode: the module graph and routes are scanned, no provider is instantiated, so neither PostgreSQL nor Better Auth is touched. `offline-env.ts` is imported first because `ConfigModule.forRoot()` validates the environment when `app.module` is loaded; it sets placeholder values that are never used to connect. Keys are sorted recursively and the file ends with a newline, so `packages/api-client/openapi.json` diffs stably.
- **Routing has one source.** `configureRouting()` (global prefix `api`, URI versioning v1) is shared by `setupApp()` and the export, so the exported paths are the served ones.
- **operationIds are `<resource><Action>`** (`teamsList`, `tasksChangeStatus`, `authSignIn`), set by the `operationIdFactory` and the hand-written auth paths, so orval emits `useTeamsList`, `useTasksChangeStatus` and models such as `TeamsListParams` instead of `TeamsController_list_v1`.
- **One seam between the client and the app: `packages/api-client/src/mutator.ts`.** Every generated call goes through `apiFetch(url, init)`. The app calls `configureApiClient({ baseUrl, getToken })` once at startup: `baseUrl` is the API origin (paths in the contract already start with `/api`), `getToken` returns the Better Auth session token or nothing (sync or async). A token is sent as `Authorization: Bearer <token>`; there is no cookie path. The mutator throws `ApiError { status, body, retryAfter }` on any non-2xx (`body` is the parsed JSON envelope, `retryAfter` the `Retry-After` header in seconds, delta or HTTP date, clamped to 1–60), returns `undefined` for an empty body, and is the only place that calls `fetch`.
- **The token never leaves the API origin.** A path is joined to `baseUrl`; an absolute URL is accepted only when it is `baseUrl` or starts with `baseUrl/` (so `http://api.test.evil`, `http://api.test@evil` and another scheme are refused), and protocol-relative `//host` is refused, all before the token is read.
- **Every request has a deadline and an id.** The mutator aborts after `timeoutMs` (15 s by default) with an error named `TimeoutError` (`ApiTimeoutError`); a caller signal (React Query's cancellation) is forwarded and stays an `AbortError`. It uses its own `AbortController` and a flag instead of `AbortSignal.timeout`/`AbortSignal.any`, which Hermes does not guarantee, and because React Native's fetch rejects with a plain `AbortError` that loses the abort reason. `X-Request-Id` is time + counter + random in base 36, which matches the API's accepted format; `crypto.randomUUID` is not available in Expo Go. A malformed JSON body surfaces as a `SyntaxError`, which the app maps to the generic message.
- **Lists page by offset.** `useTeamsListInfinite` and `useTasksListInfinite` are generated next to the plain hooks (`offset` is the page param); spread `offsetPagination` (`initialPageParam: 0`, next offset from `meta.hasNextPage`) into their `query` options. Hooks type their error as `ErrorType<ApiErrorResponseDto>` = `ApiError<ApiErrorResponseDto>`.
- **Responses are the body, not `{ data, status, headers }`** (`override.fetch.includeHttpResponseReturnType: false`): a hook's `data` is the API envelope as documented.
- **Two entry points.** `@hitss/api-client` exports the hooks, query keys, request functions, model types, `configureApiClient` and `ApiError`; `@hitss/api-client/zod` exports the zod schemas (`TeamsCreateBody`, `AuthSignInBody`, …), kept apart because their names collide with the model types. The package ships TypeScript source (no build step); the consumer's bundler compiles it.
- **Generated files are never edited by hand.** `src/generated/**` and `openapi.json` are excluded from Prettier and lint, and the `contract` CI job (`tools/ci/api-client-drift.sh`) regenerates both and fails on any difference, printing the stat and the first 200 lines of the diff. After an API contract change run `pnpm api-client:generate` and commit the result with it.

## Mobile app

- **Expo SDK 58 is pinned to the versions it bundles** (`react` 19.3.0, `react-native` 0.88.0, every `expo-*` and native module at the `bundledNativeModules.json` version) because Expo Go only ships those native binaries. Versions are exact, not ranges.
- **One React copy.** `test-renderer` and Expo's optional peers made pnpm auto-install `react`/`react-dom` 19.3.1 next to the app's 19.3.0, and two copies break hooks (`useContext` of null). `pnpm-workspace.yaml` overrides both to 19.3.0; `react-dom` is also a mobile devDependency so Expo's optional peer resolves to it.
- **Metro needs `react-native-css-interop` as a direct dependency.** NativeWind's `jsxImportSource` resolves `react-native-css-interop/jsx-runtime` from the app, which pnpm's isolated layout hides unless the app declares it.
- **Dark tokens live under `.dark:root`, not `.dark`.** With `darkMode: 'class'` css-interop recognises root variables only as `:root` and `.dark:root`; a bare `.dark` block would be compiled as a class and never switch the variables. The design spec allows changing the selector only. `ThemeProvider` reads NativeWind's color scheme, which follows the device until `colorScheme.set()` is called (theme switching, T-004-23).
- **The class catalog is checked by rendering it.** `catalog.test.tsx` compiles `global.css` with the app's Tailwind config through `nativewind/test` and asserts every catalog class resolves to a style in light and dark, which also proves nested `@apply` of custom classes (`.btn-primary { @apply btn … }`) works in NativeWind 4.2.
- **`tokens.ts` is a mirror, not a source.** It exists for values that cannot be class names (navigation theme, status bar, icon colors); `tokens.test.ts` parses `global.css` and fails on any drift.
- **Time-zone tests run in separate processes.** Jest sandboxes `process.env`, so assigning `TZ` inside a test does not change the zone. `pnpm test` reruns the date suite with `TZ=Pacific/Kiritimati` (UTC+14) and `TZ=Pacific/Pago_Pago` (UTC-11), and the suite asserts it really runs in the requested zone.
- **Jest transforms ESM-only packages.** jest-expo runs CommonJS; `msw` 2 depends on ESM-only `rettime`, `until-async` and `@open-draft/*`, so they are in the `transformIgnorePatterns` allow-list and `.mjs` goes through `babel-jest`. The pattern skips the `.pnpm/<name>@<version>` store segment and matches the inner `node_modules/<package>/`, because pnpm writes scoped names as `@scope+name` there. MSW 3 is ESM-only end to end, hence MSW 2.
- **Native modules are mapped, not mocked per test.** `jest.config.js` maps `expo-secure-store` to an in-memory fake and AsyncStorage to its official mock; `tests/setup.ts` resets both, starts MSW with `onUnhandledRequest: 'error'` and configures the api-client with no token.
- **The import rule test runs under `node --test`.** ESLint loads its flat config through dynamic `import()`, which jest rejects without `--experimental-vm-modules`, so the AC-04.15.3 fixture test (`tests/lint/*.test.mjs`) uses the Node test runner, like `packages/api-client`.
- **401 has one seam.** `createQueryClient({ onUnauthenticated })` calls the handler from both the `QueryCache` and the `MutationCache` `onError`, so no hook handles 401 itself; M2 passes the sign-out handler. Hook `data` is the full envelope; feature hooks unwrap with `select`.
- **Routes and feature components import only `use*` hooks and types from `@hitss/api-client`** (`@typescript-eslint/no-restricted-imports` with `allowImportNamePattern`). Request functions and `configureApiClient` stay in feature hooks and `src/lib`. Plain `fetch` is banned in the app; HTTP goes through the mutator or the Better Auth client.
- **Error copy never comes from the server.** `error-messages.ts` maps `error.code` to the design spec pt-BR text; an unknown code or a non-envelope body (a proxy's HTML 502) falls back to the generic message, a fetch `TypeError` is the network message and a `TimeoutError` the timeout message.

## Mobile UI kit

- **One rem is 16 pt.** NativeWind defaults to 14, which turns the spec's 4 pt grid into 3.5 pt steps (`px-4` = 14); `metro.config.js` sets `inlineRem: 16`. The rem is inlined when the CSS is compiled, so the test harness passes the same option.
- **UI tests render real styles.** `tests/renderUi.tsx` compiles `global.css` with the app's Tailwind config once per test file and registers it through `react-native-css-interop/test` with `inlineRem: 16` (`nativewind/test`'s `render` hard-codes the compile options), so tests assert resolved token colors and sizes in light and dark. Tailwind only emits classes it finds in content, so the harness safelists every class-like word in `src/**/*.tsx`.
- **Touch targets are measured, not trusted.** `expectTouchTarget` reads `minHeight`/`height` plus `hitSlop` from the rendered style. Chips are 24 pt high and reach 44 with a 10 pt vertical `hitSlop` and `min-w-touch`; segments add `min-w-touch` because `.segment` only sets the height.
- **Icons use the design-spec names.** `Icon` maps them (`circle-half`, `cloud-off`, `more`…) to MaterialCommunityIcons, the one `@expo/vector-icons` set with every glyph the spec needs, and resolves `color` from `tokens.ts` because icon fonts take a color prop, not a class. Jest maps `@expo/vector-icons/*` to a plain `View` mock: the real component loads its font through `expo-asset`, which fails outside Metro.
- **A field names its control.** `Field` passes `"<label>, obrigatório, <error>"` to its control through context (`useField`) and hides the visible label and error from screen readers, so each is read once, on the control.
- **Modals trap the screen reader.** `Sheet` and `ConfirmDialog` mark their panel `accessibilityViewIsModal`, which hides the scrim from VoiceOver, so the panel handles `onAccessibilityEscape`; Android uses `onRequestClose`. `ConfirmDialog` moves focus to Cancelar with `sendAccessibilityEvent(ref, 'focus')` (`setAccessibilityFocus` is deprecated).
- **Toasts are a store, not a context.** `showToast()` works outside React (005 mutation defaults). One toast at a time; the `Toaster` announces it and hides it after 4 s, 6 s for errors, 8 s when it has an action and a screen reader is on.
- **The color scheme comes from React Native.** `useColorSchemeName` reads `useColorScheme` from `react-native` (`useSyncExternalStore` over `Appearance`), not NativeWind's hook: css-interop's `useColorScheme` subscribes to its observable during render, so a render React discards leaves a subscriber that never mounted, and flipping the system scheme logged "Can't perform a React state update on a component that hasn't mounted yet". Both read the same `Appearance` value; `dark:` classes keep following NativeWind's own observable.
- **Equal segments, unless they cannot fit.** `SegmentedControl` splits the row equally for the three statuses. The task list filter has four options and "Em andamento" wrapped on a phone, so it is `scrollable`: segments take their label width, grow to fill the row when they fit, and the row scrolls sideways edge to edge (`-mx-4` against the screen gutter) when they do not, so a cut-off segment reads as more content instead of a clipped label.
- **RNTL 14 is async.** `render`, `rerender` and `fireEvent` return promises; tests await them. Role queries skip a `View` that has a role but is not `accessible`, so the segmented control's `radiogroup` is found by its label.

## Mobile auth and shell

- **Better Auth runs through `expoClient`, the API through the mutator.** `authClient` (`better-auth/react` + `@better-auth/expo/client`, same 1.7.7 as the API) sends `expo-origin: teamstasks://` so the server's `expo()` plugin trusts the request, and `fetchOptions.auth` sends the SecureStore token as `Bearer`. `fetchOptions.onSuccess` stores the `set-auth-token` header in SecureStore; `/api/v1` reads it through `getToken`. `expoClient` also keeps its own cookie and session cache in SecureStore (`teamstasks_cookie`, `teamstasks_session_data`), so `deleteToken` removes those keys with the token: a stale cookie would otherwise restore a session on the next `get-session`.
- **The gate is `Stack.Protected`, the index redirects by status.** `(tabs)` is guarded by a session, `(auth)` by its absence. `app/index.tsx` redirects to `/tasks` or `/sign-in` from the session status: a fixed `<Redirect href="/tasks">` loops when signed out, because a blocked route falls back to the unguarded index. SDK 58 navigators render only declared screens, so every tab is a `Tabs.Screen`.
- **The splash stays until the session is known.** `preventAutoHideAsync` runs at module load and `AuthGate` renders nothing while `useSession` is pending, so a stored session never flashes the sign-in screen.
- **401 and sign-out share the wipe, not the trigger.** `expireSession` (from the QueryCache/MutationCache `onError`) deletes the token, clears the query cache, sets the expired notice and refetches the session; concurrent 401s share one run. `signOut` awaits the server sign-out (still with the Bearer token, so the session is revoked), the token deletion, `queryClient.clear()` and every `onSessionReset` callback (filters in M4, persisted cache and queue in M5) before the gate may move. `expoClient` nulls its session atom before the sign-out request is sent, so `useAuthSession` reports `signedIn` while `signingOut` is set; without that hold the router would leave Settings before storage is wiped.
- **Sign-in errors come from the auth client, not `ApiError`.** Better Auth returns `{ error: { status, code } }` for HTTP errors and throws on a network failure, so `useSignIn` maps both: 401 → "E-mail ou senha incorretos", 429 → the rate-limit copy with `X-Retry-After` clamped to 1–60 s, a throw → the network copy. The form validates only the e-mail format and a non-empty password; the length rule belongs to sign-up and would leak policy on sign-in.
- **Auth tests isolate by file.** The Better Auth session atom is a module singleton and RNTL registers its cleanup hooks on import, so `jest.resetModules()` per test is not an option; each gate scenario is its own file under `tests/auth/`. `tests/app-harness.tsx` renders `AuthGate` with `renderRouter` and stub routes that tests override with real ones.
- **MSW starts when the setup file loads.** better-fetch keeps the `fetch` it sees when the auth client is imported, so `server.listen()` in `beforeAll` came too late and auth requests went to the real network.
- **Jest needs the app scheme and sync SecureStore.** `expo-linking` cannot read the scheme without a manifest, so `tests/setup.ts` mocks `createURL`; `expoClient` calls the synchronous `getItem`/`setItem`, so the SecureStore fake implements them.
- **No console in the app.** There is no mobile logger in MUST, so `no-console` is an error everywhere in `apps/mobile` (no allowed methods); `tests/lint/no-console.test.mjs` proves it, which is how T-004-06 keeps the token out of log output.
- **`renderRouter` uses fake timers.** Tests wait with `waitFor`/`findBy*`; a real `setTimeout` inside `act` never fires there.

## Mobile teams

- **The MSW API keeps state.** `tests/db.ts` holds teams and tasks and `tests/setup.ts` resets it before each test, so a create, rename or delete is visible to the next request: renames rewrite task chips and deletes drop them, as the API does, and tests assert on `db` that tasks survive a team deletion.
- **Test mutations are never garbage collected.** A settled mutation starts a 5-minute `gcTime` timer, which kept Jest from exiting after any test that saved something; `createTestQueryClient` sets `gcTime: Infinity` for mutations as it already did for queries.
- **A team detail starts from the list.** `useTeam` seeds `initialData` from any cached Teams list page that holds the team and passes that page's `dataUpdatedAt`, so the edit form opens at once from the list and still refetches once the copy is older than `staleTime`.
- **Double submit is blocked by a ref.** Two presses in the same tick both see `formState.isSubmitting` as false, so `useTeamForm.submit` keeps an in-flight ref set until `handleSubmit` settles. Tests press twice inside one `act`; two concurrent `fireEvent` calls overlap their `act` scopes and break the renderer for the following tests.
- **Screens stay router-free.** `TeamFormScreen` reports `onDirtyChange` and the route turns off the modal's swipe-to-dismiss while there are unsaved changes; Cancelar shows the discard dialog. Navigation callbacks come from the `app/` files, so screens are tested without a router.
- **Mutation variables follow the M5 contract.** `{ tempId, body }`, `{ id, body }`, `{ id, name }` under `mk.teams.*`, so 005's mutation defaults can take over the hooks; `tempId` is a local counter until `newTempId()` from `@/offline` lands.
- **Every route outside the groups is declared in the gate.** Expo Router registers any `app/` file as a root `Stack` screen, and a screen not listed inside a `Stack.Protected` is reachable by deep link while signed out. `AuthGate` therefore lists each signed-in route outside `(tabs)` (`teams/new`, `teams/[id]/edit`) under the signed-in guard, with its modal presentation; `tests/auth/gate-team-*` deep-link to them signed out and signed in (one file per session state, because the Better Auth session is a module singleton).

## Mobile tasks

- **Filters live per list, in memory.** `filters.store.ts` keys status and search by scope (`'all'` or the `teamId`), so the global list and each team list keep their own; nothing is persisted, so a restart starts unfiltered, and the store registers its reset with `onSessionReset()` for sign-out. `'ALL'` sends no `status`; any other value sends exactly one.
- **One tab route serves S3 and S6.** `app/(tabs)/tasks.tsx` reads `?teamId` and keys `TasksListScreen` by it, so switching between the global list and a team list remounts with that scope's filters instead of reusing scroll and query state.
- **Every list under `qk.*.lists()` is infinite.** Detail seeding (`useTaskDetail`, `useTeam`) and 005's optimistic updates read `InfiniteData` pages, so the task form's team picker also uses `useTeamsListInfinite` (one page of 100) rather than the plain list hook.
- **Undo is built at the call site.** Only `useStatusChange` knows the previous status, so it shows "Marcada como …" with Desfazer and announces "Status alterado para …"; the mutation hook itself only applies the cache effects and maps errors to a toast.
- **Overdue comes from the API.** Rows and the detail use `isOverdue` (UTC, never for DONE) and always pair it with the word "Atrasada" and an icon; the app does not recompute it from the device clock.

## Mobile finishing

- **A created team returns to the task form through a store.** The task form stays mounted under the team-form modal, so `/teams/new?from=task` hands the new team's id over `created-team.store.ts` (session-scoped, reset on sign-out) and the task form adds it while there is room; route params cannot carry a result back through `router.back()`.
- **Background refetch errors over cached data become a toast.** `useBackgroundErrorToast` shows the mapped message with Tentar novamente when a list that already has rows fails to refetch; a pull to refresh records the error it produced (`errorUpdatedAt`) so only its own "Não foi possível atualizar" toast appears.
- **The state matrix is one suite.** `tests/state-matrix.test.tsx` has one `describe` per screen of design §7 and one test per cell; offline and pending-sync cells are spec 005's, S1/S5 cells are in the auth suites.
- **Maestro selects by `testID` and seeded names.** Segments expose `<control>-<value>` ids because the status words also appear as badge labels; `tests/maestro-ids.test.ts` fails when a flow references an id the app no longer has. Flows read the Expo URL from `MAESTRO_EXPO_URL` (Maestro passes `MAESTRO_*` variables through) and run outside CI.
- **One third-party warning is muted in LogBox.** NativeWind remaps `ImageBackground` when it loads, so React Native's deprecation warning fires on every start although the app never renders one; its LogBox bar sits over the tab bar in Expo Go and swallows taps, which broke the Maestro flows. `LogBox.ignoreLogs` mutes only that message, so the console still prints it and every other warning still shows.
- **Maestro flows tame Expo Go before they test the app.** `common/open-app.yaml` turns airplane mode off (a failed offline flow would leave it on) and switches off Expo Go's floating tools button, which sits on the header actions. Flows tap a text field near its end before erasing, because `eraseText` deletes backwards from the cursor, and wait for the toast to leave before tapping a control under it. `flowsOrder` lists flows by their `name`, not the file name.
- **A held request needs an unawaited press.** RNTL 14's `fireEvent` awaits the handler, so pressing a save whose request a test holds open never returns; the matrix starts the press inside `await act(async () => button.props.onClick(...))` without awaiting the handler, and each test releases the request and waits for the result before it ends, or the late update breaks the next test's renderer.

## Mobile dev server image

- **The workspace belongs to `node` from the first copy.** NativeWind (`react-native-css-interop`) writes a `.cache` folder inside its own package in `node_modules`, and Metro and Expo write next to the app, so the non-root process must own the install. Every `COPY` into `/repo` uses `--chown=node:node` and the install runs as `node`; a `chown -R` after the install would duplicate the ~1.5 GB `node_modules` into another layer. pnpm installs with `--package-import-method copy`, because the store is a build cache mount that is gone at run time.
- **pnpm is activated at build time.** `corepack prepare pnpm@<packageManager> --activate` runs as `node`, and the final stage sets `COREPACK_ENABLE_NETWORK=0`, so a version mismatch fails at start instead of downloading. A test keeps the pinned version equal to the root `packageManager`.
- **The image is about 1.8 GB.** It holds the whole mobile workspace install: Metro and Babel need dev dependencies (`babel-preset-expo`, `tailwindcss`), and pnpm cannot drop only the test tooling. It is a local, optional dev image, never published, so the size is accepted.

## Mobile offline

- **The offline layer is TanStack Query.** Paused mutations are the queue, `PersistQueryClientProvider` stores them with the cache, and `setMutationDefaults` per key (registered in `app/_layout.tsx` before the provider restores) carries the logic that closures would lose after a restart. Feature hooks are `useMutation({ mutationKey })` only; anything passed at the call site overrides the defaults, so call sites add form-only callbacks and nothing else.
- **One lane.** Every durable mutation has `scope: { id: 'sync' }`, so changes run one at a time in the order they were made and a task can reference a team created before it offline. Bounded retries (5, exponential to 30 s, or `Retry-After`) keep one failing change from blocking the lane forever; after them the change is rolled back and explained like any rejection.
- **Rollback is per entity, not a cache snapshot.** Optimistic updates apply at `mutate` time while the request waits in the lane, so restoring a whole-cache snapshot on a later rejection would erase the optimistic state of changes queued after it. The context stores only the changed entity's previous value and position per cached page (and its detail); it is serializable, so it survives a restart with the mutation.
- **Temporary ids resolve at execution time.** `tmp-<uuid>` (expo-crypto) ids live in the caches and in mutation variables; `resolveId` maps them through `sync.store.idMap` when a mutation runs. Because the lane is serial, a missing mapping means the creation failed, so the dependant fails unsent. Details opened on a temp id follow `useResolvedId` instead of `router.setParams`, and never fetch a `tmp-` URL.
- **A change persisted mid-attempt is restored as paused.** Dehydration keeps pending mutations, but one saved while its request was in flight comes back `pending` and not `isPaused`; `resumePausedMutations` skips it and the serial lane stalls behind it. The persister marks restored pending mutations paused.
- **The persister is ours.** `createAsyncStoragePersister` throttles writes bound to one key; a write scheduled before a sign-out or user switch would land after the purge, or under the new user's key. `createOwnerPersister` binds each pending write to the owner it was taken for and drops it on `removeClient`. Only `teams`/`tasks` keys are dehydrated, so auth data and the token never reach AsyncStorage.
- **Sync waits for a server-verified session.** `onlineManager` is NetInfo AND the session gate. The gate opens only after a network `get-session` returns a user, claiming the cache for that user first (another owner's cache and queue are purged before anything renders or sends). Going offline closes it, so every reconnect is verified again; a 401 during replay closes it and keeps the mutation paused for the same user's next sign-in. Better Auth restores its cached session at launch while `isPending` is still true, and `useAuthSession` reports `loading` until it settles, so a cached-but-expired session never opens the gate.
- **A purge ends the session's changes, even mid-backoff.** TanStack v5 does not cancel the retryer of a removed mutation: one sleeping in its backoff wakes up and calls `mutationFn` again, which after a sign-out and another sign-in would send it with the new user's token. `purge()` bumps a per-client session epoch, each change records the epoch of its first attempt, and a change from an older epoch throws `StaleSessionError` before sending, stops retrying and skips its success and discard callbacks (so its rollback snapshot never lands in the new user's cache). Sign-out closes the sync gate before anything else.
- **The banner debounces only going offline.** One second of lost connection before "Você está offline…" stops flaps; leaving offline is immediate so "De volta online — sincronizando N alterações…" and "Todas as alterações sincronizadas" are seen even when the queue drains in under a second.
- **Online form errors stay in the form.** `submitDurable` awaits the server when online, so field errors (`TEAM_NAME_ALREADY_EXISTS`, `UNKNOWN_TEAMS`) land on the form and the defaults skip their warning toast; offline it queues, closes the form and shows "Salvo. Será sincronizado quando você estiver online.", and a later rejection is a toast.
- **List invalidation waits for the lane to drain** and only follows a success, so server data never overwrites the optimistic state of changes still queued.
- **The API client owns what a network failure looks like.** Expo's global `fetch` (`expo/fetch`, installed by Expo's winter runtime unless `EXPO_PUBLIC_USE_RN_FETCH` is set) rejects with a plain `Error` ("fetch failed: …"), not React Native's `TypeError`, so `apiFetch` wraps any rejection of `fetch` itself, other than an abort, in `ApiNetworkError extends TypeError`. Replay classification and error copy keep one rule (`TypeError` = network, retry) whichever fetch is installed; MSW in Jest throws Node's `TypeError`, which is why only a device showed the offline create being discarded.
- **Test harness notes.** Jest maps NetInfo to a controllable fake and `expo-crypto` to Node's `randomUUID` (jest-expo's auto-mock returns `undefined`); offline is simulated with NetInfo plus MSW network errors because `offlineFirst` still sends the first attempt. Router-level suites seed caches only after the gate has claimed the cache, or the claim's purge wipes them.
