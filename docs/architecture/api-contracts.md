# API Contracts

REST over JSON. Base path **`/api/v1`**. OpenAPI 3.1 generated by `@nestjs/swagger` from the DTOs, served at **`/docs`** (UI) and **`/docs/openapi.json`**. The OpenAPI document is the source for the generated client (`packages/api-client`). Decisions: [ADR-0005](adr/0005-rest-openapi-and-response-envelope.md), [ADR-0006](adr/0006-offset-pagination.md), [ADR-0008](adr/0008-class-validator-dtos-and-generated-client.md).

## Conventions

| Topic            | Rule                                                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Naming           | JSON fields in `camelCase`; ids are UUID strings; timestamps ISO-8601 UTC (`2026-10-20T13:00:00.000Z`); dates `YYYY-MM-DD`.                                                |
| Auth             | Every `/api/v1/*` route requires a session except `/api/v1/health/*`. Send `Authorization: Bearer <token>` (Better Auth `bearer` plugin) or the session cookie.            |
| Ownership        | All resources are scoped to the authenticated user. Another user's resource → `404`.                                                                                       |
| Success envelope | `{ "data": <resource or array>, "meta"?: { ... } }`                                                                                                                        |
| Error envelope   | `{ "error": { "code": "STRING_CODE", "message": "Human readable", "details"?: [...] , "traceId": "..." } }`                                                                |
| Validation       | Unknown fields are rejected (`400 VALIDATION_FAILED`).                                                                                                                     |
| Concurrency      | Single-resource responses carry `ETag: W/"<version>"`. `PUT`, `PATCH` and `DELETE` accept `If-Match`; mismatch → `412 PRECONDITION_FAILED`. Optional, so plain cURL works. |
| Idempotency      | `POST` accepts `Idempotency-Key` (UUID). Same key + same body within 24 h → original response replayed; same key + different body → `422 IDEMPOTENCY_KEY_REUSED`.          |
| Tracing          | Every response has `X-Request-Id`; W3C `traceparent` is honored.                                                                                                           |
| Rate limit       | 100 req/min per user (auth endpoints: 10 req/min per IP) → `429 RATE_LIMITED` with `Retry-After`.                                                                          |

## Pagination, sorting, search

Query parameters on list endpoints:

| Param    | Type   | Default      | Rules                                                                                             |
| -------- | ------ | ------------ | ------------------------------------------------------------------------------------------------- |
| `limit`  | int    | 20           | 1–100                                                                                             |
| `offset` | int    | 0            | ≥ 0                                                                                               |
| `search` | string | —            | 1–100 chars, trimmed. Case-insensitive substring match (teams: name; tasks: title + description). |
| `sort`   | string | `-createdAt` | `field` ascending, `-field` descending. Whitelist per endpoint.                                   |

List `meta`:

```json
{ "total": 42, "limit": 20, "offset": 20, "hasNextPage": true }
```

## Identity — `/api/auth/*`

Handled by Better Auth (mounted outside `/api/v1`, documented here for completeness).

| Method & path                  | Body                        | Notes                                                       |
| ------------------------------ | --------------------------- | ----------------------------------------------------------- |
| `POST /api/auth/sign-up/email` | `{ name, email, password }` | Password 8–128 chars. Returns user + session token.         |
| `POST /api/auth/sign-in/email` | `{ email, password }`       | Returns session token (header `set-auth-token`) and cookie. |
| `POST /api/auth/sign-out`      | —                           |                                                             |
| `GET /api/auth/get-session`    | —                           | Current user + session.                                     |

## Teams — `/api/v1/teams`

### Team resource

```json
{
  "id": "6f1c2b9e-1b2a-4d7e-9a51-7a0c3b8f9e10",
  "name": "Mobile",
  "colorHex": "#7C3AED",
  "description": "iOS & Android squad",
  "taskCount": 4,
  "version": 1,
  "createdAt": "2026-10-20T13:00:00.000Z",
  "updatedAt": "2026-10-20T13:00:00.000Z"
}
```

`taskCount` = non-deleted tasks assigned to the team.

| Endpoint                              | Description                                                                        | Success                           |
| ------------------------------------- | ---------------------------------------------------------------------------------- | --------------------------------- |
| `GET /teams?limit&offset&search&sort` | List teams. `sort` ∈ `name`, `createdAt`, `updatedAt`.                             | `200 { data: Team[], meta }`      |
| `GET /teams/:id`                      | Get one team.                                                                      | `200 { data: Team }` + `ETag`     |
| `POST /teams`                         | Create. Body `{ name, colorHex, description? }`.                                   | `201 { data: Team }` + `Location` |
| `PUT /teams/:id`                      | Replace. Body `{ name, colorHex, description? }` (omitted `description` → `null`). | `200 { data: Team }`              |
| `DELETE /teams/:id`                   | Soft delete; unassigns the team from its tasks.                                    | `204`                             |

Validation: `name` 2–50 chars (unique per user, case-insensitive) · `colorHex` `^#[0-9A-Fa-f]{6}$` · `description` ≤ 280 chars.

## Tasks — `/api/v1/tasks`

### Task resource

```json
{
  "id": "1d2e3f40-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
  "title": "Implement login screen",
  "description": "Email + password, error states",
  "status": "IN_PROGRESS",
  "dueDate": "2026-10-31",
  "completedAt": null,
  "isOverdue": false,
  "teams": [
    {
      "id": "6f1c2b9e-1b2a-4d7e-9a51-7a0c3b8f9e10",
      "name": "Mobile",
      "colorHex": "#7C3AED"
    }
  ],
  "version": 3,
  "createdAt": "2026-10-20T13:00:00.000Z",
  "updatedAt": "2026-10-21T09:12:00.000Z"
}
```

`teams` is embedded (id, name, color) so the app can render color chips without extra requests.

| Endpoint                                            | Description                                                                         | Success                           |
| --------------------------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------- |
| `GET /tasks?teamId&status&search&limit&offset&sort` | List tasks.                                                                         | `200 { data: Task[], meta }`      |
| `GET /tasks/:id`                                    | Get one task.                                                                       | `200 { data: Task }` + `ETag`     |
| `POST /tasks`                                       | Create. Body `{ title, description?, status?, dueDate?, teamIds? }`.                | `201 { data: Task }` + `Location` |
| `PUT /tasks/:id`                                    | Replace editable fields. Body `{ title, description?, status, dueDate?, teamIds }`. | `200 { data: Task }`              |
| `PATCH /tasks/:id/status`                           | Quick action. Body `{ status }`.                                                    | `200 { data: Task }`              |
| `DELETE /tasks/:id`                                 | Soft delete.                                                                        | `204`                             |

Filters:

- `teamId` — UUID; tasks assigned to that team. Unknown/foreign team → empty list (not an error).
- `status` — one value or comma-separated list: `status=PENDING,IN_PROGRESS`.
- `search` — title or description contains the term.
- `sort` ∈ `createdAt`, `updatedAt`, `dueDate`, `title`, `status` (nulls last for `dueDate`). Ties broken by `id` for stable pagination.

Validation: `title` 3–120 chars · `description` ≤ 2000 · `status` enum · `dueDate` `YYYY-MM-DD` · `teamIds` 0–10 distinct UUIDs of the user's teams.

## Health — `/api/v1/health`

| Endpoint            | Purpose                                         |
| ------------------- | ----------------------------------------------- |
| `GET /health/live`  | Process is up (no dependencies).                |
| `GET /health/ready` | Database reachable. Used by Docker healthcheck. |

Health endpoints return Terminus' native format (not the envelope) for tool compatibility.

## Error codes

| HTTP | `code`                                                  | When                                                                     |
| ---- | ------------------------------------------------------- | ------------------------------------------------------------------------ |
| 400  | `VALIDATION_FAILED`                                     | DTO validation failed. `details: [{ field, message }]`.                  |
| 401  | `UNAUTHENTICATED`                                       | Missing/invalid/expired session.                                         |
| 404  | `TEAM_NOT_FOUND` · `TASK_NOT_FOUND` · `ROUTE_NOT_FOUND` | Unknown id, or owned by another user.                                    |
| 409  | `TEAM_NAME_ALREADY_EXISTS`                              | Duplicate team name for the user.                                        |
| 412  | `PRECONDITION_FAILED`                                   | `If-Match` doesn't match current version. `details: { currentVersion }`. |
| 422  | `UNKNOWN_TEAMS`                                         | `teamIds` contains ids not found for the user. `details: { teamIds }`.   |
| 422  | `TOO_MANY_TEAMS`                                        | More than 10 teams.                                                      |
| 422  | `IDEMPOTENCY_KEY_REUSED`                                | Same key, different payload.                                             |
| 429  | `RATE_LIMITED`                                          | Throttled.                                                               |
| 500  | `INTERNAL_ERROR`                                        | Unexpected. Message is generic; details only in logs (by `traceId`).     |

Example:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed",
    "details": [
      {
        "field": "title",
        "message": "title must be longer than or equal to 3 characters"
      }
    ],
    "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"
  }
}
```

## Request examples (cURL)

```bash
API=http://localhost:3000

# Sign in as the seeded demo user and keep the token
TOKEN=$(curl -si -X POST $API/api/auth/sign-in/email \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@teams-tasks.dev","password":"Demo@1234"}' \
  | grep -i '^set-auth-token:' | cut -d' ' -f2 | tr -d '\r')

# List teams
curl -s "$API/api/v1/teams?limit=10" -H "Authorization: Bearer $TOKEN"

# Create a team
curl -s -X POST $API/api/v1/teams -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -H "Idempotency-Key: $(uuidgen)" \
  -d '{"name":"Platform","colorHex":"#0EA5E9","description":"Infra & tooling"}'

# Pending or in-progress tasks of a team, matching "login", by due date
curl -s "$API/api/v1/tasks?teamId=<teamId>&status=PENDING,IN_PROGRESS&search=login&sort=dueDate&limit=20&offset=0" \
  -H "Authorization: Bearer $TOKEN"

# Create a task in two teams
curl -s -X POST $API/api/v1/tasks -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write release notes","dueDate":"2026-11-05","teamIds":["<teamA>","<teamB>"]}'

# Quick action: mark as done (with optimistic concurrency)
curl -s -X PATCH $API/api/v1/tasks/<taskId>/status -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -H 'If-Match: W/"3"' \
  -d '{"status":"DONE"}'

# Delete
curl -s -X DELETE $API/api/v1/tasks/<taskId> -H "Authorization: Bearer $TOKEN" -o /dev/null -w '%{http_code}\n'
```

A runnable [Bruno](https://www.usebruno.com/) collection lives in `tools/bruno/`, and `.http` files in `tools/http/`.
