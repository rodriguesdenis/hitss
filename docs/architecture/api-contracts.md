# API Contracts

REST over JSON. Base path **`/api/v1`**. OpenAPI 3.1 generated by `@nestjs/swagger` from the DTOs, served at **`/docs`** (UI) and **`/docs/openapi.json`**. The OpenAPI document is the source for the generated client (`packages/api-client`). Decisions: [ADR-0005](adr/0005-rest-openapi-and-response-envelope.md), [ADR-0006](adr/0006-offset-pagination.md), [ADR-0008](adr/archive/0008-class-validator-dtos-and-generated-client.md).

## Conventions

| Topic            | Rule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Naming           | JSON fields in `camelCase`; team/task ids are UUID strings (a malformed path `:id` → `400 VALIDATION_FAILED`, `details: [{ field: "id" }]`); timestamps ISO-8601 UTC (`2026-10-20T13:00:00.000Z`); dates `YYYY-MM-DD`.                                                                                                                                                                                                                                                                                          |
| Auth             | Every `/api/v1/*` route requires a session except `/api/v1/health/*`. Send `Authorization: Bearer <token>` (the `set-auth-token` from sign-in; Better Auth `bearer` plugin). A session cookie alone is **not** accepted on `/api/v1` (`401`, ADR-0020); cookies are only used by Better Auth on `/api/auth/*`. With no ambient credential there is no CSRF check.                                                                                                                                               |
| Ownership        | All resources are scoped to the authenticated user. Another user's resource → `404`; another user's team id in a task's `teamIds` → `422 UNKNOWN_TEAMS`, the same answer as for a team that never existed.                                                                                                                                                                                                                                                                                                      |
| Success envelope | `{ "data": <resource or array>, "meta"?: { ... } }`                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Error envelope   | `{ "error": { "code": "STRING_CODE", "message": "Human readable", "details"?: [...] , "traceId": "..." } }` `traceId`: the OpenTelemetry trace id, or the `X-Request-Id` when tracing is disabled. `message` is a fixed text per code; it never echoes the request or a domain/driver message.                                                                                                                                                                                                                  |
| Validation       | Unknown fields are rejected (`400 VALIDATION_FAILED`). Team `name` and task `title` reject control characters (`\p{Cc}`) → `400 VALIDATION_FAILED`. Descriptions (team and task) reject control characters except line breaks (`\n`, `\r`) → `400 VALIDATION_FAILED`. Only `application/json` bodies are parsed (up to 100 kB); a body of another type is not read, so its fields are missing and validation answers `400 VALIDATION_FAILED`.                                                                   |
| String lengths   | Every length limit (team `name`/`description`, task `title`/`description`, `search`, password) counts **Unicode code points**, measured after trimming for trimmed fields (passwords are never trimmed). Matches class-validator `isLength` and PostgreSQL `varchar(n)`.                                                                                                                                                                                                                                        |
| Concurrency      | **Last write wins** ([ADR-0020](adr/0020-simplify-architecture-for-the-hiring-test.md)): no `ETag` is sent and `If-Match` is ignored, so there is no `412`. Every write still increments the resource's `version`, returned as data.                                                                                                                                                                                                                                                                            |
| Idempotency      | **Planned, not implemented** (T-002-05 / T-003-18, COULD; [ADR-0019](adr/archive/0019-idempotency-keys.md)). The header is ignored today. Design: `POST` accepts `Idempotency-Key` (UUID); same key + same body within 24 h → original response replayed (same status, body and `Location`, plus `Idempotent-Replayed: true`); same key + different body → `422 IDEMPOTENCY_KEY_REUSED`; same key while the first request is still in flight → `409 IDEMPOTENCY_REQUEST_IN_PROGRESS` with `Retry-After: 1`.     |
| Tracing          | Every response has `X-Request-Id`. A client-sent `X-Request-Id` is echoed only if it matches `^[A-Za-z0-9._-]{1,128}$`; otherwise a new one is generated. W3C `traceparent` is honored.                                                                                                                                                                                                                                                                                                                         |
| Rate limit       | `/api/v1/*`: Nest throttler with two limits — per IP `RATE_LIMIT_IP_MAX` req/min (env, default 300), checked **before authentication**, and per user `RATE_LIMIT_MAX` req/min (env, default 100) after authentication → `429 RATE_LIMITED` with `Retry-After`. `/api/auth/*`: Better Auth's built-in limiter per IP (forwarded headers not trusted unless configured) — sign-up / sign-in / sign-out 10 req/min, get-session 100 req/min — answering `429` in Better Auth's native format with `X-Retry-After`. |

## Pagination, sorting, search

Query parameters on list endpoints:

| Param    | Type   | Default      | Rules                                                                                                                                               |
| -------- | ------ | ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `limit`  | int    | 20           | 1–100. Digits only: `2.5`, `ten` or an empty value → `400 VALIDATION_FAILED` on `limit`.                                                            |
| `offset` | int    | 0            | 0–1 000 000 (an upper bound that keeps `OFFSET` in range). Past the end → empty page, not an error.                                                 |
| `search` | string | —            | 1–100 chars after trimming (empty/blank → `400 VALIDATION_FAILED`). Case-insensitive substring match (teams: name; tasks: title + description).     |
| `sort`   | string | `-createdAt` | `field` ascending, `-field` descending, one field only. Whitelist per endpoint (an enum in OpenAPI). Ties are broken by `id` in the same direction. |

Unknown query parameters → `400 VALIDATION_FAILED` naming the parameter. List `meta`:

```json
{ "total": 42, "limit": 20, "offset": 20, "hasNextPage": true }
```

## Identity — `/api/auth/*`

Handled by Better Auth (mounted outside `/api/v1`, documented here for completeness). Responses and errors, including `429`, use **Better Auth's native format**, not our envelope — a documented exception like health (constitution §IV.2).

| Method & path                  | Body                        | Notes                                                       |
| ------------------------------ | --------------------------- | ----------------------------------------------------------- |
| `POST /api/auth/sign-up/email` | `{ name, email, password }` | Password 8–128 chars. Returns user + session token.         |
| `POST /api/auth/sign-in/email` | `{ email, password }`       | Returns session token (header `set-auth-token`) and cookie. |
| `POST /api/auth/sign-out`      | —                           |                                                             |
| `GET /api/auth/get-session`    | —                           | Current user + session.                                     |

## Teams — `/api/v1/teams`

### Team resource

```json
{
  "id": "6f1c2b9e-1b2a-4d7e-9a51-7a0c3b8f9e10",
  "name": "Mobile",
  "colorHex": "#7C3AED",
  "description": "iOS & Android squad",
  "taskCount": 4,
  "version": 1,
  "createdAt": "2026-10-20T13:00:00.000Z",
  "updatedAt": "2026-10-20T13:00:00.000Z"
}
```

`taskCount` = non-deleted tasks assigned to the team.

| Endpoint                              | Description                                                                                     | Success                           |
| ------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------- |
| `GET /teams?limit&offset&search&sort` | List teams. `sort` ∈ `name` (case-insensitive), `createdAt`, `updatedAt`; `search` on the name. | `200 { data: Team[], meta }`      |
| `GET /teams/:id`                      | Get one team.                                                                                   | `200 { data: Team }`              |
| `POST /teams`                         | Create. Body `{ name, colorHex, description? }`.                                                | `201 { data: Team }` + `Location` |
| `PUT /teams/:id`                      | Replace. Body `{ name, colorHex, description? }` (omitted `description` → `null`).              | `200 { data: Team }`              |
| `DELETE /teams/:id`                   | Soft delete; unassigns the team from its tasks in the same transaction.                         | `204`                             |

Validation: `name` 2–50 chars (unique per user, case-insensitive) · `colorHex` `^#[0-9A-Fa-f]{6}$` · `description` ≤ 280 chars.

## Tasks — `/api/v1/tasks`

### Task resource

```json
{
  "id": "1d2e3f40-5a6b-4c7d-8e9f-0a1b2c3d4e5f",
  "title": "Implement login screen",
  "description": "Email + password, error states",
  "status": "IN_PROGRESS",
  "dueDate": "2026-10-31",
  "completedAt": null,
  "isOverdue": false,
  "teams": [
    {
      "id": "6f1c2b9e-1b2a-4d7e-9a51-7a0c3b8f9e10",
      "name": "Mobile",
      "colorHex": "#7C3AED"
    }
  ],
  "version": 3,
  "createdAt": "2026-10-20T13:00:00.000Z",
  "updatedAt": "2026-10-21T09:12:00.000Z"
}
```

`teams` is embedded (id, name, color), ordered by `name`, so the app can render color chips without extra requests. `isOverdue` = `status != DONE` and `dueDate` before **today in UTC**.

| Endpoint                                            | Description                                                                                                | Success                           |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- | --------------------------------- |
| `GET /tasks?teamId&status&search&limit&offset&sort` | List tasks.                                                                                                | `200 { data: Task[], meta }`      |
| `GET /tasks/:id`                                    | Get one task.                                                                                              | `200 { data: Task }`              |
| `POST /tasks`                                       | Create. Body `{ title, description?, status?, dueDate?, teamIds? }`.                                       | `201 { data: Task }` + `Location` |
| `PUT /tasks/:id`                                    | Replace editable fields. Body `{ title, description?, status, dueDate?, teamIds }`.                        | `200 { data: Task }`              |
| `PATCH /tasks/:id/status`                           | Quick action. Body `{ status }`. Same status as current → no-op: `200` with the task (version not bumped). | `200 { data: Task }`              |
| `DELETE /tasks/:id`                                 | Soft delete.                                                                                               | `204`                             |

Filters:

- `teamId` — UUID; tasks assigned to that team, each with **all** its teams embedded. An unknown, deleted or another user's team → empty list with `total` 0 (not an error).
- `status` — one value, a comma-separated list (`status=PENDING,IN_PROGRESS`) or the parameter repeated (`status=PENDING&status=DONE`). Repeats are tolerated; an unknown, lower-case or empty value (`PENDING,`) → `400` on `status`.
- `search` — title or description contains the term, ignoring case; `%`, `_` and `\` match literally.
- `sort` ∈ `createdAt`, `updatedAt`, `dueDate`, `title`, `status` (nulls last for `dueDate`; `status` uses lifecycle order `PENDING` < `IN_PROGRESS` < `DONE`, not alphabetical). Ties broken by `id` for stable pagination.

Validation: `title` 3–120 chars · `description` ≤ 2000 · `status` enum (exact upper case) · `dueDate` a real calendar date `YYYY-MM-DD` (past dates allowed) · `teamIds` array of UUIDs of the user's teams; duplicates → `400 VALIDATION_FAILED`; 11–100 → `422 TOO_MANY_TEAMS` (the domain rule, checked before team existence); more than 100 → `400 VALIDATION_FAILED` (DTO hard cap `@ArrayMaxSize(100)`, a payload-size guard only). On `PUT`, `title`, `status` and `teamIds` are required, and an omitted `description` or `dueDate` is cleared. `PATCH /status` accepts `status` and nothing else.

## Health — `/api/v1/health`

| Endpoint                   | Purpose                                                                                                                                                |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/v1/health/live`  | Process is up (no dependencies): `200 { "status": "ok" }`.                                                                                             |
| `GET /api/v1/health/ready` | Database reachable: `200 { "status": "ready", "checks": { "database": "up" } }`, or `503` with `"unavailable"` / `"down"`. Used by Docker healthcheck. |

Health endpoints are public, never throttled, and return this plain body (not the envelope) for tool compatibility; it names the failing check and nothing about the failure.

## Error codes

| HTTP | `code`                                                                         | When                                                                                                                                                                                                                                                                                                                  |
| ---- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400  | `VALIDATION_FAILED`                                                            | DTO validation failed (incl. malformed path `id`, blank `search`, duplicate `teamIds`, more than 100 `teamIds`). `details: [{ field, message }]`. Also a malformed JSON body. Also a body or query nested deeper than 32 levels (`field: body`/`query`). At most 50 details, each `field`/`message` ≤ 100 characters. |
| 401  | `UNAUTHENTICATED`                                                              | Missing/invalid/expired session.                                                                                                                                                                                                                                                                                      |
| 404  | `TEAM_NOT_FOUND` · `TASK_NOT_FOUND` · `ROUTE_NOT_FOUND`                        | Unknown id, or owned by another user. `ROUTE_NOT_FOUND`: no route matches the path and method.                                                                                                                                                                                                                        |
| 409  | `TEAM_NAME_ALREADY_EXISTS`                                                     | Duplicate team name for the user.                                                                                                                                                                                                                                                                                     |
| 409  | `IDEMPOTENCY_REQUEST_IN_PROGRESS`                                              | **Planned** (see Idempotency). A request with the same `Idempotency-Key` is still being processed. `Retry-After: 1`.                                                                                                                                                                                                  |
| 422  | `UNKNOWN_TEAMS`                                                                | `teamIds` contains ids that are not the user's live teams. `details: { teamIds }` lists exactly those ids; a deleted, another user's and a never-existing team give the same body.                                                                                                                                    |
| 422  | `TOO_MANY_TEAMS`                                                               | 11–100 distinct `teamIds` on one task (above 100 → `400`). `details: { max: 10, received }`.                                                                                                                                                                                                                          |
| 422  | `IDEMPOTENCY_KEY_REUSED`                                                       | **Planned** (see Idempotency). Same key, different payload or different route.                                                                                                                                                                                                                                        |
| 429  | `RATE_LIMITED`                                                                 | Throttled (`/api/v1/*`). `Retry-After` in seconds; no `X-RateLimit-*` headers.                                                                                                                                                                                                                                        |
| 4xx  | HTTP status name (e.g. `PAYLOAD_TOO_LARGE`, `METHOD_NOT_ALLOWED`, `FORBIDDEN`) | Any other client error raised by the framework or the body parser, e.g. a JSON body over 100 kB → `413 PAYLOAD_TOO_LARGE`. The code is the status's `HttpStatus` name and the message is fixed (it never echoes the request).                                                                                         |
| 500  | `INTERNAL_ERROR`                                                               | Unexpected. Message is generic; details only in logs (by `traceId`).                                                                                                                                                                                                                                                  |

Example:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request validation failed.",
    "details": [
      {
        "field": "title",
        "message": "title must be longer than or equal to 3 characters"
      }
    ],
    "traceId": "4bf92f3577b34da6a3ce929d0e0e4736"
  }
}
```

## Request examples (cURL)

```bash
API=http://localhost:3000

# Sign in as the seeded demo user and keep the token
TOKEN=$(curl -si -X POST $API/api/auth/sign-in/email \
  -H 'Content-Type: application/json' \
  -d '{"email":"demo@teams-tasks.dev","password":"Demo@1234"}' \
  | grep -i '^set-auth-token:' | cut -d' ' -f2 | tr -d '\r')

# List teams
curl -s "$API/api/v1/teams?limit=10" -H "Authorization: Bearer $TOKEN"

# Create a team
curl -s -X POST $API/api/v1/teams -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Platform","colorHex":"#0EA5E9","description":"Infra & tooling"}'

# Pending or in-progress tasks of a team, matching "login", by due date
curl -s "$API/api/v1/tasks?teamId=<teamId>&status=PENDING,IN_PROGRESS&search=login&sort=dueDate&limit=20&offset=0" \
  -H "Authorization: Bearer $TOKEN"

# Create a task in two teams
curl -s -X POST $API/api/v1/tasks -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"title":"Write release notes","dueDate":"2026-11-05","teamIds":["<teamA>","<teamB>"]}'

# Quick action: mark as done
curl -s -X PATCH $API/api/v1/tasks/<taskId>/status -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"status":"DONE"}'

# Rename a team (full replacement; last write wins)
curl -s -X PUT $API/api/v1/teams/<teamId> -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"name":"Platform","colorHex":"#0EA5E9"}'

# Delete
curl -s -X DELETE $API/api/v1/tasks/<taskId> -H "Authorization: Bearer $TOKEN" -o /dev/null -w '%{http_code}\n'
```

A runnable [Bruno](https://www.usebruno.com/) collection lives in `tools/bruno/`, and `.http` files in `tools/http/`; both cover the auth requests so far.
