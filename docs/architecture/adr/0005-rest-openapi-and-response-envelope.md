# ADR-0005 — REST + OpenAPI with response/error envelopes

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** software-architect, nestjs-specialist

## Context

The brief asks for a REST-style CRUD API with listing metadata and request examples (cURL). The consumer is our own mobile app, but evaluators will also call the API by hand. The client must be generated from a machine-readable contract ([ADR-0008](0008-class-validator-dtos-and-generated-client.md)), and errors must be predictable enough for the app to map them to UI messages and for logs to be correlated with traces.

## Decision drivers

- Easy to exercise with cURL/Bruno; matches the brief's vocabulary.
- A standard contract format that tooling (Swagger UI, orval, Bruno) understands.
- Consistent shape for every success and every error, so a single client mutator can handle them.
- Stable, documented error **codes** (not just HTTP statuses or messages).
- HTTP caching/concurrency semantics available (`ETag`, `If-Match`).

## Considered options

### 1. REST + OpenAPI 3.1 via `@nestjs/swagger`, with envelopes (chosen)

- **+** Every tool in our chain speaks OpenAPI; Swagger UI at `/docs` doubles as live documentation.
- **+** HTTP semantics (status codes, `Location`, `ETag`, `Retry-After`) do real work.
- **+** Envelope `{ data, meta? }` leaves room for pagination metadata without changing the resource schema.
- **−** Envelopes add one level of nesting; bare-resource purists prefer headers for pagination.

### 2. GraphQL (Apollo / Mercurius)

- **+** Client picks fields; one round trip for task + team chips.
- **−** The brief speaks REST/CRUD; cURL examples become verbose; HTTP caching, rate limiting per route and `ETag` concurrency are harder; resolver-level N+1 needs DataLoader. Our embedded `teams` summary already solves the only nested read.

### 3. tRPC / ts-rest

- **+** End-to-end types with no codegen.
- **−** Couples the app to TypeScript server internals; no neutral contract for cURL/Bruno users; less idiomatic in Nest.

### 4. REST without envelopes (bare resources, pagination in `Link`/`X-Total-Count` headers)

- **+** Leaner payloads, RFC 8288 friendly.
- **−** Headers are easy to lose in proxies and awkward in generated hooks; the brief explicitly asks for "metadata" in the listing response.

## Decision outcome

- **Style:** resource-oriented REST, JSON, base path **`/api/v1`** (URI versioning via Nest `enableVersioning({ type: URI })`). Breaking changes → `/api/v2` (constitution §IV.3). Identity routes live at `/api/auth/*` (owned by Better Auth, [ADR-0007](0007-better-auth.md)).
- **Contract:** OpenAPI **3.1** generated by `@nestjs/swagger` from DTOs; served at `/docs` and `/docs/openapi.json`; exported to a file at build for client generation.
- **Success envelope:** `{ "data": T, "meta"?: { total, limit, offset, hasNextPage } }`, produced by a global **response interceptor**. Controllers return plain view objects; the interceptor wraps them. Swagger decorators (`@ApiEnvelopedResponse(TeamDto)`, `@ApiPaginatedResponse(TeamDto)`) describe the wrapped schema so the generated client is typed correctly.
- **Error envelope:** `{ "error": { code, message, details?, traceId } }`, produced by a global **exception filter** that maps:
  - class-validator failures → `400 VALIDATION_FAILED` with `details: [{ field, message }]`,
  - `DomainError` subclasses → their HTTP status and code (table in [API contracts](../api-contracts.md#error-codes)),
  - throttling → `429 RATE_LIMITED`, unknown route → `404 ROUTE_NOT_FOUND`,
  - anything else → `500 INTERNAL_ERROR` with a generic message (full error logged with the same `traceId`).
- **Exclusions:** `204` responses have no body; health endpoints keep Terminus' native format for tool compatibility; Better Auth routes keep Better Auth's format.
- **Headers:** `Location` on `201`, `ETag` on single-resource responses ([ADR-0015](0015-optimistic-concurrency.md)), `X-Request-Id` on all responses, `traceparent` honored.
- **Hardening:** `helmet`, `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true, transform: true })`, `@nestjs/throttler` with per-user and per-IP limits.

## Consequences

**Positive**

- One client mutator handles every response: unwrap-or-throw a typed `ApiError` keyed by `code`.
- `traceId` in every error lets a user report be traced in SigNoz in one search.
- The contract is visible and testable (e2e tests assert envelope shape; CI diff on `openapi.json`).

**Negative**

- Interceptor + Swagger decorator pair must stay in sync; mitigated by a custom decorator that applies both.
- Two error formats exist at the edges (Better Auth, Terminus); documented and handled in the client.

**Neutral**

- The constitution's error envelope lists `{ code, message, details? }`; `traceId` is an additive field.
