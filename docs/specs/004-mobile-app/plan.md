### API client (`packages/api-client`)

- **Generation:** `orval.config.ts` reads `apps/api` OpenAPI (`/docs/openapi.json`, exported to `packages/api-client/openapi.json` by the API build so generation does not need a running server). Two outputs:
  - `src/generated/endpoints/*.ts` — `client: 'react-query'`, `httpClient: 'fetch'`, `mode: 'tags-split'`, `override.mutator: { path: './src/mutator.ts', name: 'customFetch' }`, `override.fetch.includeHttpResponseReturnType: false` (hooks return the body, not `{ data, status, headers }`), `override.query: { useQuery: true, useInfinite: true, useInfiniteQueryParam: 'offset' }` for list operations, `signal: true`.
  - `src/generated/zod/*.ts` — `client: 'zod'` for request bodies and params.
- **Mutator `customFetch<T>(url, init)`** (injected config via `configureApiClient({ baseUrl, getAuthHeaders, onUnauthenticated })` called by the app at startup):
  1. Resolve the URL against `baseUrl` (`EXPO_PUBLIC_API_URL`); an absolute URL whose origin is not `baseUrl` is **rejected** (`ApiError('FOREIGN_URL')`, never sent), and auth headers (`Cookie` from `authClient.getCookie()`) are attached only when the final URL starts with `baseUrl` (security T3). Set `Accept`/`Content-Type: application/json`, `Accept-Language` = current app language, `X-Request-Id` = `randomUUID()` (always matches `[A-Za-z0-9._-]{1,128}`).
  2. Pass through per-call headers set by hooks: `If-Match` (`PUT`/`DELETE`), `Idempotency-Key` (`POST` only, D31).
  3. Timeout 15 s via `AbortSignal.any([callerSignal, AbortSignal.timeout(15000)])` (fallback polyfill if unavailable) → `ApiError('TIMEOUT')`.
  4. Network failure → `ApiError({ code: 'NETWORK', status: 0 })`.
  5. `204` → `undefined`. `2xx` → parsed JSON **success envelope** `{ data, meta? }` exactly as typed by the generated schema (lists need `meta`); single-resource screens unwrap with `select: (r) => r.data`. The `ETag` value is redundant with `version` in the body, so no header plumbing is needed.
  6. Non-2xx → parse error envelope → throw `ApiError { status, code, message, details, traceId, retryAfter }`; `retryAfter` (ms) is parsed from `Retry-After` whenever present (`429 RATE_LIMITED`, `409 IDEMPOTENCY_REQUEST_IN_PROGRESS`) and **clamped to 1–60 s** (security T5). `401` additionally calls `onUnauthenticated()`. Better Auth endpoints (`/api/auth/*`) are called through `authClient`, not this mutator; their `429`s carry `X-Retry-After`, parsed by the shared `parseRetryAfter()` helper (`Retry-After` or `X-Retry-After`, same clamp) used by the auth hooks.
- `ApiError` and `isApiError`, `errorMessageKey(err)` (→ `errors.<CODE>` with fallback `errors.INTERNAL_ERROR`) and `fieldErrors(err)` (maps `VALIDATION_FAILED.details[]` → `{ field: messageKey }`) are exported from `packages/api-client/src/errors.ts` and unit-tested.
- The app never hand-writes request/response types (constitution IV).

### Server state rules

- **QueryClient defaults** (ADR-0010, `src/shared/query/query-client.ts`): `staleTime: 30s`, `gcTime: 24h` (needed for 005 persistence), `networkMode: 'offlineFirst'`, `retry: (n, e) => isRetryable(e) && n < 3` with exponential backoff (network/5xx/timeout and `409 IDEMPOTENCY_REQUEST_IN_PROGRESS` after `Retry-After`; never other 4xx), `refetchOnWindowFocus` wired to `AppState` via `focusManager`.
- **Query key factory** (`src/shared/query/keys.ts`, ADR-0010 `taskKeys` / `teamKeys`, built on orval's generated key helpers for the params part); the generated hooks receive these keys via `query: { queryKey }` so invalidation is prefix-based and independent of URLs (shown here as one `qk` object):

```ts
export const qk = {
  teams: {
    all: ['teams'] as const,
    lists: () => [...qk.teams.all, 'list'] as const,
    list: (p: TeamListParams) => [...qk.teams.lists(), p] as const,
    detail: (id: string) => [...qk.teams.all, 'detail', id] as const,
  },
  tasks: {
    all: ['tasks'] as const,
    lists: () => [...qk.tasks.all, 'list'] as const,
    list: (p: TaskListParams) => [...qk.tasks.lists(), p] as const, // p includes teamId; status omitted when 'ALL'
    detail: (id: string) => [...qk.tasks.all, 'detail', id] as const,
  },
  session: ['session'] as const,
};
```

- **Mutation keys** (stable, used by 005 `setMutationDefaults`): `['tasks','create']`, `['tasks','update']`, `['tasks','changeStatus']`, `['tasks','delete']`, `['teams','create']`, `['teams','update']`, `['teams','delete']`. Each mutation's variables are plain serializable objects `{ taskId?, body?, baseVersion?, idempotencyKey? }`; `idempotencyKey` exists only on the two create mutations (`POST`, D31).
- **Invalidation rules:**

| Mutation      | Cache effect on success                                                                                                                                                                        |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create task   | `invalidate(tasks.lists)`, `invalidate(teams.lists)` (task counts) ; `setQueryData(tasks.detail(id))`                                                                                          |
| Update task   | `setQueryData(tasks.detail(id))`, `invalidate(tasks.lists)`, `invalidate(teams.lists)` (assignment may change counts)                                                                          |
| Change status | `setQueryData(tasks.detail(id))`, `invalidate(tasks.lists)` (status filters)                                                                                                                   |
| Delete task   | `removeQueries(tasks.detail(id))`, `invalidate(tasks.lists)`, `invalidate(teams.lists)`                                                                                                        |
| Create team   | `invalidate(teams.lists)`                                                                                                                                                                      |
| Update team   | `setQueryData(teams.detail(id))`, `invalidate(teams.lists)`, `invalidate(tasks.all)` (embedded chips name/color)                                                                               |
| Delete team   | `removeQueries(teams.detail(id))`, `invalidate(teams.lists)`, `invalidate(tasks.all)`                                                                                                          |
| Sign out      | await `persister.removeClient()` (005) and session deletion from SecureStore, then `queryClient.clear()` + reset local stores, then navigate (T7)                                              |
| 401           | clear **queries only** (`queryClient.getQueryCache().clear()`); paused mutations stay persisted under `rq:<ownerId>` and are resumed or discarded after the next sign-in (005, security T1/T2) |

- **Detail from list:** `useTaskDetail(id)` uses `initialData` from any cached list page containing the task (`initialDataUpdatedAt` from that query) so the detail renders instantly and refreshes in the background.
- **Infinite lists:** `useInfiniteListTasks(params, { query: { queryKey: qk.tasks.list(params), initialPageParam: 0, getNextPageParam: (last) => last.meta.hasNextPage ? last.meta.offset + last.meta.limit : undefined, maxPages: 10 } })`, `limit: 20`. `FlatList` with `onEndReachedThreshold={1.5}`, `RefreshControl` → `refetch()` (refetches from page 1).

### Forms

- `features/tasks/hooks/useTaskForm.ts`: `taskFormSchema = createTaskBody.extend({ title: z.string().trim().min(3, 'form.title.min').max(120, 'form.title.max'), description: z.string().max(2000, 'form.description.max').optional(), dueDate: z.string().regex(/^\d{4}-\d{2}-\d{2}$/).nullable().optional(), teamIds: z.array(z.string().uuid()).max(10, 'form.teams.max') })`. Messages are i18n keys translated by `<Field>`. `mode: 'onTouched'`, `reValidateMode: 'onChange'` (error clears as soon as valid — AC-04.7.2).
- Server errors: `fieldErrors(err)` → `setError(field, { message })`; `UNKNOWN_TEAMS.details.teamIds` → remove ids + `setError('teamIds', 'form.teams.removed')`; `PRECONDITION_FAILED` → conflict dialog (reload = `refetch` + `reset(values)`).
- Dirty-cancel guard via `usePreventRemove(isDirty && !isSubmitSuccessful, …)` from navigation → confirm dialog.
- Team form: `teamFormSchema = createTeamBody.extend({ name: z.string().trim().min(2).max(50), colorHex: z.string().regex(/^#[0-9A-Fa-f]{6}$/).transform(s => s.toUpperCase()), description: z.string().trim().max(280).optional() })`.
- Double-submit: submit handler returns early while `isSubmitting` / `mutation.isPending`; creation also carries an `Idempotency-Key` generated once per form submission (AC-04.9.6).

### Auth

- `src/features/auth/auth-client.ts`: `createAuthClient({ baseURL: env.apiUrl, plugins: [expoClient({ scheme: Constants.expoConfig.scheme, storagePrefix: 'teamstasks', storage: SecureStore })] })`. The scheme is `teamstasks`, declared once in `app.config.ts` (ADR-0009) and read from there; it must equal the API's `APP_SCHEME` (spec 001, default `teamstasks`), which feeds Better Auth `trustedOrigins`.
- Root layout: `const { data: session, isPending } = authClient.useSession()`; `SplashScreen.preventAutoHideAsync()` until `!isPending`. `(app)/_layout.tsx` returns `<Redirect href="/sign-in" />` without a session and `(auth)/_layout.tsx` redirects to `/tasks` with one (ADR-0009); `Stack.Protected` is an equivalent alternative on SDKs that ship it.
- `app/_layout.tsx` calls `setupApiClient({ getAuthHeaders, onUnauthenticated })` (`src/shared/config/api-client.ts`, which adds `baseUrl` from `shared/config/env` and `Accept-Language`) with `getAuthHeaders = () => ({ Cookie: authClient.getCookie() })` (`expoClient` keeps the cookie in `expo-secure-store`); `onUnauthenticated` → `authClient.signOut()` (local), clear the **query** cache only (never `queryClient.clear()`, which would drop queued mutations — security T2), set a one-shot flag so Sign in shows `errors.UNAUTHENTICATED`.
- Sign out (Settings, US-04.16 MUST — T-004-11): `await` `persister.removeClient()` (005) and the SecureStore session deletion (`authClient.signOut()`) **before** navigating to Sign in (security T7).
- Sign-in/up error mapping: Better Auth error codes `INVALID_EMAIL_OR_PASSWORD` → `auth.invalidCredentials`; **both** `USER_ALREADY_EXISTS` and `USER_ALREADY_EXISTS_USE_ANOTHER_EMAIL` → `auth.emailTaken` (security T6; a contract test pins the codes against the Better Auth version in use); `429` → `errors.RATE_LIMITED` with seconds from `X-Retry-After`.
- Server-side requirements (spec 001): `expo()` plugin on the Better Auth server and the app scheme in `trustedOrigins`.

### Theme & i18n

- Theming mechanism (ADR-0011, D29): every color role is a CSS variable `--color-<role>` holding `R G B` channels, defined in `global.css` under `:root` (light) and `.dark` (dark; only the selector changes if NativeWind needs `.dark:root`), and `tailwind.config.js` maps it (`surface: 'rgb(var(--color-surface) / <alpha-value>)'`, no `*-dark` keys). Catalog classes therefore use one utility per role (`bg-canvas`, `bg-surface`, `text-fg`, `text-fg-muted`, `border-border-strong`, `bg-status-done-bg`…) and switch theme by variable swap; `dark:` appears only for the exceptions listed in design spec §2 (today only `.card` `shadow-sm dark:shadow-none`). Typography classes are `.type-*` (not `.text-*`, which collides with Tailwind size utilities); the status filter is the `.segmented` track + `.segment` items (single-select, D32). Variable and class names are owned by the [design spec](../../design/design-spec.md) §1.6/§2 (coordinated with the designer); the plan does not redefine them.
- `src/shared/theme/ThemeProvider.tsx` — MUST baseline: NativeWind's default `system` color scheme (dark variables apply when the device is dark); COULD (T-004-23): reads `preferences.theme` and calls `colorScheme.set('light' | 'dark' | 'system')`. In both cases `StatusBar` style, icon colors and the React Navigation theme (`src/shared/theme/navigation-theme.ts`) read `src/shared/theme/tokens.ts`, a TS mirror `{ light, dark }` of hex values keyed by role name for non-`className` consumers (owned by the mobile specialist; a unit test parses `global.css` and asserts parity).
- `contrastingText(hex)` and `needsOutline(hex, surfaceHex)` in `src/shared/theme/contrast.ts` implement design spec §3; table-driven tests use §1.3.
- `src/shared/i18n/index.ts` — MUST baseline: resource `en` only, every string through keys; COULD (T-004-24): adds `pt-BR` and language = preference (`system | en | pt-BR`, D33); `system` (default) resolves to `getLocales()[0].languageCode === 'pt' ? 'pt-BR' : 'en'`; `Intl.DateTimeFormat` for dates (Hermes supports `Intl`); due dates parsed as local calendar dates (`YYYY-MM-DD` → `new Date(y, m-1, d)`) never via `Date.parse` (BR-04.10).
- A unit test asserts both locale files have identical key sets.

### Environment & running on a device

- `app.config.ts` reads `EXPO_PUBLIC_API_URL`, validated with zod in `src/shared/config/env.ts` (fail fast with a readable red-screen message); outside `__DEV__` the schema requires an `https://` URL (security T4).
- A physical device in Expo Go **cannot reach `localhost`** of the dev machine. Options documented in `apps/mobile/README.md`:
  - same Wi-Fi: `EXPO_PUBLIC_API_URL=http://<LAN-IP>:3000` (e.g. `192.168.0.10`; find via `ipconfig getifaddr en0` / `hostname -I`); WSL2 users need port forwarding or mirrored networking;
  - Android emulator: `http://10.0.2.2:3000`; iOS simulator: `http://localhost:3000`;
  - restricted networks: tunnel the **API** (e.g. `cloudflared tunnel --url http://localhost:3000`) — `expo start --tunnel` only tunnels Metro, not the API.
- API must allow the app origin/scheme (Better Auth `trustedOrigins`) — dependency on spec 001.

## Contract

Screens → endpoints (no duplication of [api-contracts.md](../../architecture/api-contracts.md)):

| Screen                           | Endpoints                                                                                    | Errors handled specifically                                                                              |
| -------------------------------- | -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Sign in / Sign up                | `POST /api/auth/sign-in/email`, `POST /api/auth/sign-up/email`, `GET /api/auth/get-session`  | invalid credentials, email taken, `RATE_LIMITED`                                                         |
| Settings (sign-out, MUST)        | `POST /api/auth/sign-out`                                                                    | —                                                                                                        |
| Teams list                       | `GET /teams?limit=20&offset&search&sort=name`                                                | `NETWORK`, `INTERNAL_ERROR`, `RATE_LIMITED`                                                              |
| Team form                        | `GET /teams/:id`, `POST /teams`, `PUT /teams/:id`, `DELETE /teams/:id`                       | `TEAM_NAME_ALREADY_EXISTS`, `VALIDATION_FAILED`, `PRECONDITION_FAILED`, `TEAM_NOT_FOUND`                 |
| Tasks list (global / `?teamId=`) | `GET /tasks?teamId&status&search&sort&limit=20&offset`; `GET /teams/:id` for the team header | as Teams list; `teamId` of a deleted team → `GET /teams/:id` `TEAM_NOT_FOUND` drives the not-found state |
| Task detail                      | `GET /tasks/:id`, `PATCH /tasks/:id/status`, `DELETE /tasks/:id`                             | `TASK_NOT_FOUND`, `PRECONDITION_FAILED`                                                                  |
| Task form                        | `GET /tasks/:id`, `GET /teams` (picker), `POST /tasks`, `PUT /tasks/:id`                     | `VALIDATION_FAILED`, `UNKNOWN_TEAMS`, `TOO_MANY_TEAMS`, `PRECONDITION_FAILED`, `IDEMPOTENCY_KEY_REUSED`  |

Headers sent by mutations: `If-Match: W/"<baseVersion>"` on `PUT` and `DELETE` (not on the status `PATCH`: toggle = last write wins, [ADR-0015](../../architecture/adr/archive/0015-optimistic-concurrency.md)); `Idempotency-Key` only on `POST` (creations), generated once per user action ([ADR-0019](../../architecture/adr/archive/0019-idempotency-keys.md), D31): `PUT`/`PATCH` are naturally idempotent and a replayed `DELETE` answered `404` counts as success.

## Data

No server schema changes. Device-side data: session cookie in SecureStore (encrypted, Keychain/Keystore); filters and preferences in AsyncStorage; query cache persistence is added in 005.

## Security considerations

- Session material only in `expo-secure-store`; never in AsyncStorage, logs or query cache.
- Sign-out and `401` clear the query cache, persisted cache (005) and per-user stores (filters).
- No secrets in the app bundle: `EXPO_PUBLIC_*` values are public by definition (API URL only).
- Error messages shown to users never include server `message`/stack text; only mapped copy (BR-04.9). `traceId` is logged in development for support.
- Release builds use HTTPS only: `env.ts` rejects a non-`https` `EXPO_PUBLIC_API_URL` when `!__DEV__` (T4), plus ATS / cleartext disabled; local HTTP is allowed in development only.
- Session cookie is sent only to the configured API origin; foreign absolute URLs are refused by the mutator (T3).
- Ownership is enforced by the API (`404` for foreign ids); the app treats it as not found (no existence leak).

## Observability

- Every request carries `X-Request-Id` (`randomUUID()`, within the API's accepted `[A-Za-z0-9._-]{1,128}`); `ApiError.traceId` is logged (dev) with the route, enabling correlation in SigNoz (spec 006).
- `console` logging wrapped by `src/shared/config/logger.ts` (no-op in production builds; never logs bodies or headers).
- Out of scope: client-side OpenTelemetry/crash reporting (listed as production improvement).
