# Traceability Matrix

Brief requirement → epic → story (priority) → acceptance criteria → scenarios → planned test level → task. Generated from `docs/specs/*/spec.md`, `docs/specs/*/*.feature`, `docs/specs/*/tasks.md` and the traceability table of `docs/brief/README.md` by `tools/ci/traceability.mjs` (`pnpm traceability`; the CI `static` job fails when this file is stale). Only the structural part is committed so that parallel pull requests do not conflict: which ACs have automated tests is computed in CI from the `AC-…` ids that start test titles and reported in the job summary. Owner: qa-engineer. Do not edit rows by hand: fix the spec, the `.feature` tag or the task `Covers:` line and regenerate.

**Conventions.** Priority is the story priority in `spec.md` (scenario tags `@must/@should/@could` must equal it). _Level_ is the planned level (unit · integration · e2e = API supertest · component = RNTL · maestro · review · ci) derived from the scenario kind and spec; it is a plan, refined in each task's _Done when_. A task covers an AC when its `Covers:` line names it.
