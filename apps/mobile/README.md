# Teams & Tasks — mobile app

The Expo app for Teams & Tasks: sign in, browse teams and tasks, filter by team and status, and create, edit, change the status of and delete tasks and teams. It runs in **Expo Go** (no native build) against the API started with `docker compose up`. UI copy is pt-BR.

Stack: Expo SDK 58 · Expo Router (typed routes) · NativeWind 4 with the [design spec](../../docs/design/design-spec.md) tokens · TanStack Query 5 with hooks generated by orval ([`@hitss/api-client`](../../packages/api-client)) · Zustand + immer · react-hook-form + zod · Better Auth (Bearer token in `expo-secure-store`). Product spec: [004 mobile app](../../docs/specs/004-mobile-app/spec.md).

## Prerequisites

- Docker with Compose, for the API and its database.
- Node.js 24 and pnpm 10 (`corepack enable`).
- One of:
  - a phone with **Expo Go for SDK 58** (Play Store / App Store) on the **same Wi-Fi** as the computer;
  - the Android emulator (Android Studio AVD, e.g. one named `hitss`) with Expo Go installed;
  - the iOS simulator (macOS only).

## 1. Start the API

From the repository root:

```sh
docker compose up -d --build --wait
```

No root `.env` is needed (copy `.env.example` to `.env` only to override settings, e.g. `API_PORT`). The API listens on port **3000** on every interface, migrates and seeds itself. The seed creates the demo account:

| E-mail                 | Password    |
| ---------------------- | ----------- |
| `demo@teams-tasks.dev` | `Demo@1234` |

Check it from the computer: `curl http://localhost:3000/api/v1/health/live`.

## 2. Point the app at the API

```sh
cp apps/mobile/.env.example apps/mobile/.env
```

Set `EXPO_PUBLIC_API_URL` to the API origin **as the device sees it** (no trailing path):

| Where the app runs                  | `EXPO_PUBLIC_API_URL`                                            |
| ----------------------------------- | ---------------------------------------------------------------- |
| Phone on the same Wi-Fi             | `http://<computer LAN IP>:3000`, e.g. `http://192.168.0.10:3000` |
| Android emulator                    | `http://10.0.2.2:3000` (the emulator's alias for the host)       |
| Android emulator with `adb reverse` | `http://localhost:3000` after `adb reverse tcp:3000 tcp:3000`    |
| iOS simulator                       | `http://localhost:3000`                                          |

A phone cannot use `localhost`: that is the phone itself. Find the LAN IP with `ipconfig` (Windows), `ipconfig getifaddr en0` (macOS) or `hostname -I` (Linux). Outside development the app accepts only `https://` URLs.

### WSL2

Docker Desktop publishes the API on Windows, but Metro runs inside WSL, so the device also has to reach WSL's port 8081.

- **Mirrored networking (recommended).** In `%UserProfile%\.wslconfig` set `[wsl2]` `networkingMode=mirrored`, then `wsl --shutdown`. WSL then shares the Windows interfaces: use the Windows LAN IP for a phone, `10.0.2.2` for the emulator, and allow ports 3000 and 8081 through the Windows firewall for private networks.
- **Without mirrored networking**, start Metro with `--tunnel` (`pnpm --filter @hitss/mobile start --tunnel`) and keep `EXPO_PUBLIC_API_URL` on the Windows LAN IP.

## 3. Start Metro and open the app

```sh
pnpm install
pnpm --filter @hitss/mobile start
```

- **Phone:** scan the QR code with the camera (iOS) or with Expo Go (Android).
- **Android emulator on Windows (AVD `hitss`):** start the AVD from Android Studio, open Expo Go and enter `exp://10.0.2.2:8081` (or press `a` in the Expo CLI when `adb` is on the same side as Metro).
- **iOS simulator:** press `i`.

Sign in with the demo account. Teams are on the **Times** tab; tapping a team opens its tasks.

`.env` changes are read when Metro starts: restart it with `pnpm --filter @hitss/mobile start -c` after editing.

## Scripts

Run from the repository root with `pnpm --filter @hitss/mobile <script>`, or from `apps/mobile` with `pnpm <script>`.

| Script      | What it does                                                                      |
| ----------- | --------------------------------------------------------------------------------- |
| `start`     | Starts Metro for Expo Go                                                          |
| `android`   | Starts Metro and opens the Android emulator                                       |
| `ios`       | Starts Metro and opens the iOS simulator                                          |
| `lint`      | ESLint and the dependency-cruiser architecture rules                              |
| `typecheck` | `tsc --noEmit`                                                                    |
| `test`      | Jest component tests (MSW, no API needed), time-zone runs and the lint-rule tests |
| `e2e`       | Maestro flows in `tests/maestro` against a running app (see below)                |
| `export`    | Bundles the Android app to `dist/` (checks the production bundle builds)          |

## End-to-end flows (Maestro)

`tests/maestro` holds the main journeys: sign in and out, team tap filtering tasks, title validation, and task create / status change / edit / delete. They run locally, outside CI, against the seeded API in Expo Go on an Android emulator or device.

1. Install the [Maestro CLI](https://docs.maestro.dev/getting-started/installing-maestro) and start the API, Metro and the emulator as above.
2. Reset the data to the seed (`docker compose down -v && docker compose up -d --build --wait`) so the flows see the demo tasks.
3. Run, with the Expo URL the emulator uses:

```sh
MAESTRO_EXPO_URL=exp://10.0.2.2:8081 pnpm --filter @hitss/mobile e2e
```

The flows select elements by `testID` and by the seeded names; a Jest test checks that every id they use exists in the app.

## Testing offline

The app works offline: lists and details already seen stay readable, and every change (create, edit, status change, delete of tasks and teams) shows immediately, is marked **Sincronização pendente** and waits in one ordered queue that survives closing the app. When the connection returns the queue is sent in the order the changes were made, then the lists refresh; the banner under the header says **De volta online — sincronizando N alterações…** and then **Todas as alterações sincronizadas**. A change the server can no longer apply (task deleted elsewhere, team name taken, unknown teams) is reverted with a warning toast and dropped; temporary failures are retried. Signing in needs a connection, and signing out with pending changes asks first because they are discarded.

- **Jest** covers it without a device: `pnpm --filter @hitss/mobile test` runs the offline suites in `tests/offline` (restart and replay, session gate, user switch, sign-out wipe, optimistic updates and rollbacks).
- **Maestro** (`tests/maestro/offline.yaml`, part of `pnpm --filter @hitss/mobile e2e`) turns airplane mode on in an **Android emulator**, creates, changes and deletes tasks, turns it off and waits for the sync. iOS simulators have no airplane mode: disconnect the Mac's network instead and follow the same steps by hand.
- **Restart while offline** is covered by Jest only: Expo Go reloads the bundle from Metro on a cold start, so it cannot relaunch without a connection. By hand: change something offline, close the app, reconnect and reopen it; the changes are still pending and then sync.
- A creation whose answer is lost on a flaky connection may be created twice when it is resent (no idempotency keys, ADR-0020).

## Troubleshooting

| Symptom                                                                             | Fix                                                                                                                                                                                    |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Não foi possível conectar ao servidor. Verifique sua conexão." on sign-in or lists | The device cannot reach `EXPO_PUBLIC_API_URL`. Open that URL plus `/api/v1/health/live` in the device's browser; fix the IP, firewall or WSL networking, then restart Metro with `-c`. |
| Red screen "EXPO_PUBLIC_API_URL is not set"                                         | Create `apps/mobile/.env` from `.env.example` and restart Metro.                                                                                                                       |
| Expo Go says the project needs a different SDK                                      | Install Expo Go for SDK 58 (update the app; on the emulator, reinstall it from the Expo CLI prompt).                                                                                   |
| Expo Go cannot load the bundle (timeout on `exp://…:8081`)                          | Metro is not reachable: same Wi-Fi, firewall for 8081, WSL mirrored networking, or start with `--tunnel`.                                                                              |
| "Muitas requisições. Tente novamente em N s." on sign-in                            | The API rate-limits sign-in attempts; wait the seconds shown.                                                                                                                          |
| "Sua sessão expirou. Entre novamente."                                              | The token was rejected (for example after `docker compose down -v` reset the database); sign in again.                                                                                 |

## Where things are

- `app/` — Expo Router routes only; screens get their params and navigation callbacks from here.
- `src/features/{auth,teams,tasks}` — screens, hooks and forms per feature.
- `src/ui` — the UI kit (buttons, fields, chips, badges, toasts, sheets, dialogs, states).
- `src/theme` — `global.css` tokens and `@apply` classes, the theme provider and the contrast rules.
- `src/lib` — API client setup, query client and keys, cache effects, error copy, dates.
- `tests/` — Jest setup, the MSW handlers and in-memory API, render helpers, Maestro flows.

Non-obvious decisions are recorded in [design notes](../../docs/architecture/design-notes.md#mobile-app).
